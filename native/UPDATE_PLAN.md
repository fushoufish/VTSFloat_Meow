# VTSFloat_Meow 自动更新实施计划

状态：已接入本地源码。构建版本号由 native/CMakeLists.txt 统一设置，正式发布时须与 Git 标签一致。

## 1. 目标与职责

保留单文件便携程序的使用方式。主程序内嵌一个临时 PowerShell 更新脚本，用户选择更新时才释放、隐藏运行，任务结束后清理，不再单独分发 `VTSFloat_Meow_updater.exe`。

- 主程序：发现当前文件位置、检查版本、显示提示、下载并校验、提交当前设置、显示下载进度与最终结果。
- PowerShell：等待旧进程退出、备份并替换文件、启动新版、验证新版就绪、触发成功提示、失败恢复、清理更新文件。
- GitHub 正式发布流程：提供最终 EXE，供 Release API 返回附件大小和 SHA-256。

检查、下载和等待均在后台进行，不阻塞模型渲染、窗口消息或个性化界面。

## 2. 当前代码需要处理的接入点

- `overlay_layered.cpp` 已有获取当前 EXE 路径、WinHTTP、设置读写、正常退出和重启基础逻辑，可复用适合的部分。
- 当前个性化面板走关闭/取消流程会还原修改。更新前必须新增“提交当前编辑”的路径，不能直接发送关闭消息后假设修改已保存。
- 当前设置写入封装不返回失败状态。更新专用保存必须检查写入结果，并确认数据落盘。
- 当前重启辅助逻辑包含等待 VTS 的行为。更新重启不依赖 VTS 是否打开，需单独实现。
- 程序版本和 Windows 文件版本由 CMake 项目版本统一生成。
- GitHub 工作流构建并校验 EXE。发布时将最终 EXE 上传为正式 Release 的附件 VTSFloat_Meow.exe。

## 3. 版本号比较

使用数字分段比较，不使用字符串排序、小数或提交哈希判断新旧。

正式版本支持可选 `v` 前缀，以及 `主版本.次版本`、`主版本.次版本.补丁版本`；缺失的补丁位补零。版本显示保留发布方的完整标签，内部比较使用标准化的三个整数。

| 输入 | 标准化 | 预期 |
| --- | --- | --- |
| `v1.2.2` | `1, 2, 2` | 小于 `1.3` |
| `1.3` | `1, 3, 0` | 等于 `1.3.0` |
| `1.3.2` | `1, 3, 2` | 大于 `1.3` |
| `1.2.10` | `1, 2, 10` | 大于 `1.2.9` |
| `2.0` | `2, 0, 0` | 大于 `1.99.99` |

逐段比较，首次不同的数字决定大小。只有远端版本严格大于当前编译版本才提示更新；相等不重复更新，更低不降级。

首版仅接收正式版本，过滤草稿与预发布版本。非法格式、负数、溢出及缺少必需信息视为该源响应无效，不猜测版本、不执行文件。

GitHub 页面里的短提交号只能用于定位源码；程序版本负责比较大小，SHA-256 负责校验下载文件。

## 4. GitHub 原生与节点 1

版本信息来自 GitHub 正式 Release。原生检查失败后，通过节点 1 重试一次。两条路线均未取得有效信息时，GUI 显示“检查失败”。

| 路线 | 检查入口 |
| --- | --- |
| GitHub 原生 | https://api.github.com/repos/fushoufish/VTSFloat_Meow/releases/latest |
| 节点 1 | https://gh-proxy.com/https://api.github.com/repos/fushoufish/VTSFloat_Meow/releases/latest |

程序检查 Release 标签、正式发布状态、EXE 文件名、字节数、SHA-256 和固定标签下载地址。原生返回有效结果后结束本轮检查，低于或等于本机版本时显示“未发现新版本”。连接错误、超时、限流或响应内容无效时切换路线。检查在后台运行，节点请求和响应大小设有上限。

选择更新后，程序锁定版本标签和 SHA-256，再按原生、节点 1 的顺序下载同一文件。节点 1 在原始 EXE 地址前加上代理域名。下载后校验字节数、SHA-256、PE 架构和 Windows 文件版本。两条路线均失败时显示“下载更新失败”，原程序继续运行。

发布流程以最终上传到 GitHub Release 的 EXE 为准。GitHub API 提供该附件的大小与摘要。GitHub Actions 在构建正式版本标签时核对 EXE 文件版本。使用节点 1 检查时，版本信息也经该代理传输，文件一致性校验依赖其正确转发 Release 摘要。

三个节点的历史实测见同目录 UPDATE_PROXY_RESEARCH.md。

## 5. 顶部提示与用户选择

主 GUI 上方使用同一行布局：

`存在新版本：v1.3.2，是否更新？  [暂不更新] [更新并重启] [×]`

- `暂不更新`：关闭本次提示，之后可手动点击“检查更新”。
- `更新并重启`：开始更新事务，下载时保留旧程序运行；显示阶段与下载进度，避免重复触发。
- `×`：仅关闭本次运行的提示，不修改持久偏好；下次启动仍可再次自动提示。
- 默认焦点/回车行为不触发更新，保留在“暂不更新”。

鼠标悬停在工具栏的 GitHub 图标上可查看当前版本。点击“检查更新”后才查询版本，选择“更新并重启”后才开始下载。

提示不进入模型渲染内容。适配现有主题、UI 缩放、DPI 和语言，保持文本与按钮同一行、垂直居中；小屏幕通过测量文本和调整提示区域宽度处理，不将按钮拆成第二行。

未发现更高版本时，手动检查显示“未发现新版本”；后台检查不重复显示此状态。

## 6. 文件位置、缓存和保存

每次发起检查时从当前运行进程读取 EXE 真实完整路径和文件名，不相信旧缓存、当前工作目录或固定的 `VTSFloat_Meow.exe` 名称。用户自行改名、移动程序后仍替换当前正在运行的文件。

更新状态目录由 `ConfigPath()` 的父目录推导，位于 `%LOCALAPPDATA%\VTSFloat_Meow\VTSFloat_Meow-updates`。每次任务使用唯一 ID，记录原 EXE 路径、当前版本、目标版本、原进程身份、暂存和备份路径、校验值、阶段以及通信凭据。

路径/任务记录写入失败：丢弃本次更新任务，保持原程序运行，不增加确认对话框。临时文件只按本次任务的明确路径清理。

下载校验完成后、旧程序退出前：

1. 从所有打开的个性化编辑控件提交当前值，结束仅用于界面演示的预览状态，避免“取消面板”撤销用户修改。
2. 保存个性化、窗口位置、快捷键和相关用户设置，检查保存结果。
3. 保存失败则停止本次更新并显示简短失败状态，不继续退出和覆盖程序，不要求用户二次确认。
4. 保存成功后冻结本次待退出界面的进一步修改，再进入替换阶段，避免保存后用户又改动设置。

## 7. 更新事务顺序

1. 主程序确认版本并下载新版到任务暂存文件；下载完成前不触碰原 EXE。
2. 检查文件大小、SHA-256、PE 格式及目标架构；校验失败删除本次下载，保持旧版运行。
3. 预检原目录写入/替换权限、剩余空间和 PowerShell 可用性，将待替换文件暂存到原 EXE 同一目录，以支持同卷替换。
4. 提交并保存用户设置，落盘任务状态，释放内嵌 PowerShell 脚本。
5. 隐藏启动更新脚本，完成握手并确认其已接管任务后，旧程序按现有正常退出流程关闭，恢复必要的 VTS 临时状态。
6. 更新脚本等待原进程实际退出和单实例锁释放；超时不盲目覆盖正在运行的 EXE。
7. 再次核验暂存文件，使用支持备份的同卷替换操作，将旧 EXE 保存为带任务 ID 的备份；新版取得原文件名和原路径。
8. 通过结构化参数启动新版，记录本次新建进程身份，传入任务 ID 和一次性通信信息。
9. 等待新版报告“设置已载入、GUI 已建立、消息循环能响应、实际版本正确”，并经过短暂稳定观察。未连接 VTS、暂无模型也属于正常启动。
10. PowerShell 发送一次性“显示更新成功”指令，新版主 GUI 显示：`更新成功，当前版本号为 v1.3.2`，并返回已显示确认。
11. 将本次事务记为成功，再清理旧版 EXE 备份、下载暂存、临时脚本与任务通信资源；更新进程退出。

所有路径按数据传递，兼容中文、空格和特殊字符，不拼接可执行的超长命令。PowerShell 使用隐藏窗口、无用户配置的非交互方式运行；脚本使用当前进程范围的执行策略。启动或握手失败时保留正在运行的旧版。

## 8. 成功提示必须由更新脚本触发

应用与 PowerShell 通过每用户缓存中的任务目录交换原子写入的 JSON 信号。每条信号校验任务令牌、进程 PID、创建时间和版本。

- 每次更新随机生成一次性令牌，限制为当前用户的通信端点，并核对本次更新进程、新进程身份及目标版本。
- 新版只上报自身就绪状态；必须收到有效更新任务的成功指令才显示成功提示。
- 普通启动、首次下载启动、仅有相同版本号、缓存里存在旧任务文件，均不能自行触发成功提示。
- 成功指令只消费一次；GUI 已显示后返回确认，不等待用户手动关闭提示才完成清理。
- 新版消息循环卡死、版本不符、很快崩溃或握手超时，不能仅因进程存在就判定成功。

## 9. 旧版清理与失败恢复

旧版备份需要清理，但必须在新版通过启动检查、更新脚本触发成功提示并收到确认后删除。

| 失败阶段 | 处理 |
| --- | --- |
| 检查、下载、校验或保存失败 | 原程序继续运行，清理本次无用暂存 |
| PowerShell 启动/接管失败 | 不退出原程序，不替换文件 |
| 原进程未退出或替换失败 | 确认实际磁盘状态；原文件受影响时恢复备份，能恢复则启动旧版 |
| 新版无法启动、提前崩溃或未就绪 | 结束/等待本次新建进程退出，恢复旧 EXE 并启动，显示更新失败 |
| 无法安全停止新版或恢复旧文件 | 保留可恢复的备份和状态记录，告知恢复失败，不删除唯一可用旧版 |
| 新版已成功，备份暂时被占用无法删除 | 不撤销成功；标记待清理，下次启动只重试删除本次已提交任务的文件 |
| 更新中断电/进程被终止 | 根据持久事务阶段和实际文件状态恢复；未确认成功的备份不得直接清除 |

回滚前只处理本次任务记录的进程，禁止按进程名批量结束程序。设置和用户文件不在清理范围内。当前版本沿用现有 INI 格式，回滚沿用保存后的个性化设置。

清理只删除本次任务拥有且验证过绝对路径的备份、暂存和脚本。不能遍历删除所有名为 VTSFloat_Meow 的文件，也不能清空个性化缓存目录。

## 10. 代码位置

- updater.cpp / updater.h 负责版本、GitHub 请求、下载校验及更新任务。
- overlay_layered.cpp 接入 GitHub 悬停菜单、单行提示和重启前保存。
- updater.ps1 作为资源内嵌到 EXE，负责替换、启动确认、回滚与清理。
- CMakeLists.txt 定义编译与文件版本，GitHub Actions 核对正式标签。

## 11. 验收项目

- 数字版本比较：覆盖上述表格、非法版本、版本相等/低于本机、草稿和预发布过滤。
- 顺序重连覆盖原生成功、原生失败后节点 1 成功、两路均失败以及取消。
- 下载切换覆盖同一标签与校验值、无效响应和错误文件。两路均失败时保留旧程序。
- 用户选择：启动时无网络检查。手动检查可用，选择“暂不更新”或 × 会关闭本次提示。
- 设置：个性化面板未点保存也能保留当前修改；写入失败不退出；正常取消面板行为不被破坏。
- 路径：EXE 改名、中文/空格路径、工作目录不同、缓存或程序目录不可写、磁盘空间不足。
- 事务：下载中断、错误哈希、被占用文件、脚本启动失败、新版崩溃、启动超时、IPC 确认失败、回滚及中途终止。
- 清理：成功后本次旧 EXE 备份和暂存消失；清理失败可重试；失败时保留必要恢复文件；不删除配置及用户文件。
- 提示：普通首次启动绝不显示“更新成功”；只有更新脚本有效指令触发一次；VTS 未启动不误报新版失败。
- UI：现有多语言、DPI/UI 缩放、最小支持窗口宽度下单行布局正确；下载不阻塞悬浮渲染。
- 完成有意义的版本/源决策单元测试、隔离更新集成测试、现有 CTest 和本地化检查，再准备正式发布。

本地验证包括真实 GitHub 版本检查、模拟原生失败时的节点 1 更新、双路失败、设置保存失败、中文与空格路径下的同名替换、新版未就绪时的回滚，以及中断后恢复和备份清理。CTest 三项与本地化检查均通过。
