# 分辨率性能采集

在工具栏打开“调试”，选择“分辨率基准采集（49组 × 24条）”。开始前的说明弹窗会列出测试分辨率、每张 GPU 的预计耗时，并提醒采集期间不要运行游戏、渲染或其他高负载任务。多显卡电脑可以选择只测试当前 GPU，或测试全部可自动切换的 GPU；选择全部后，程序会依次重启 VTS 与覆盖层并继续下一张 GPU 的任务。

VTSFloat_Meow 会自动切换自身渲染分辨率，并通过 Windows 窗口接口调整 VTube Studio 客户区尺寸。程序始终以实际收到的 Spout2 纹理尺寸进行最终校验；如果自动调整后 8 秒内仍未匹配，才会暂时隐藏模型窗口并提示手动设置。检测到两端分辨率完全匹配后，程序先预热 4 秒，再按调试性能栏的 2 秒统计周期记录数据。采集结束或停止时会恢复 VTS 与 VTSFloat_Meow 原来的窗口位置和尺寸。

测试采用完整的 7×7 组合矩阵，共 49 组。每个程序渲染分辨率固定时，VTS 分辨率都按表中顺序从高到低测试一遍：

| 类型 | 分辨率顺序 |
| --- | --- |
| VTS Spout2 原生分辨率 | 3840×2160、2560×1440、1920×1080、1600×900、1280×720、960×540、640×480 |
| VTSFloat_Meow 渲染分辨率 | 640×480、960×540、1280×720、1600×900、1920×1080、2560×1440、3840×2160 |

每组写入 24 条原始样本，不额外写入汇总行。某项无法取得的数据会在 CSV 中留空，不会写成 0。

采集目录位于“文档\VTSFloat_Meow Benchmarks\capture_日期_时间”。每张 GPU 生成一个独立 CSV，文件名采用该张 GPU 任务的创建时间，例如：

- `20260909_012345.csv`

同一次“测试全部 GPU”的文件都放在同一个采集目录内，不会把不同 GPU 的样本混写，也不会生成 XLSX 或其他报表文件。CSV 第一行是 `CPU`、`GPU`、`RAM`、`GPU_RAM`、`START_TIME`、`STOP_TIME`、VTS/VTSM 平均/最低/最高帧数等字段，第二行是实际硬件和整轮统计值；空一行后才是逐条原始样本表。每条记录时间采用 `yyyy:hh:mm:ss:mmm` 格式，例如 `2026:00:31:08:127`。

CSV 包含 VTS 原生分辨率、程序缩放分辨率、性能评级、对齐率、接收延迟、缩放延迟、上屏延迟、CPU 占用、GPU 占用、显存、内存、VTS 帧数和程序帧数。字段口径如下：

- VTS 原生分辨率取实际收到的 Spout2 纹理尺寸。
- CPU、GPU、内存均为 VTSFloat_Meow 进程的数据。
- 显存优先取 VTSFloat_Meow 进程的专用显存；系统性能计数器不可用时，回退为当前适配器本地显存占用。
- VTS 帧数来自已连接的 VTube Studio Plugins API 实时统计。
- 程序帧数是 VTSFloat_Meow 在同一统计周期内实际完成的上屏更新 FPS。
- 对齐率按较小像素数除以较大像素数计算。
- 顶部 `CPU` 与 `GPU` 写入硬件型号，`RAM` 与 `GPU_RAM` 写入实际容量（GB）；帧数统计在该张 GPU 的任务结束或停止时回填。

VTube Studio Plugins API 可以读取窗口尺寸和帧率统计，但没有设置 VTube Studio 主画面或 Spout2 输出分辨率的请求。采集器因此使用 Windows 窗口接口自动调整 VTS，并以 Spout2 接收结果验证；自动调整失败时回退为手动提示。API 中可设置的自定义分辨率属于 NDI 输出，不适用于这组 Spout2 测试。
